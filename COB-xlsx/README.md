# COB-xlsx

A formula-driven Excel port of the COB segmented mortgage / cost-of-borrowing
engine (see [`COB-ts`](../COB-ts), [`COB-py`](../COB-py)). No code required to
use it -- open `COB_Calculator.xlsx` and edit the blue input cells.

This directory also ships a **second, sibling workbook**,
`COB_Calculator_CA.xlsx` (built by `build_workbook_ca.py`), implementing the
Canadian Cost-of-Borrowing (COB) disclosure calculator from
[`docs/new-req/006-cost-of-borrowing-disclosure.md`](../docs/new-req/006-cost-of-borrowing-disclosure.md)
-- semi-annual mortgage compounding, trigger rate, and the regulatory
average-balance APR formula, none of which exist in the US-style engine above.
See that spec's "Excel implementation notes" section for why this is a
separate file rather than new sheets in `COB_Calculator.xlsx`.

**New to the workbook? Start with [`MANUAL.md`](MANUAL.md)** -- a sheet-by-sheet
usage reference with cell-level tables and worked examples using the data
already in the file (both workbooks).

See [`docs/new-req/005-excel-workbook.md`](../docs/new-req/005-excel-workbook.md)
for the design writeup (why Excel formulas needed a different approach than the
code engines, two real bugs the Python-engine cross-check caught, and how every
number in the workbook was verified).

## Regenerating the workbook(s)

Each `.xlsx` file is generated by its own script -- treat the scripts as the
source of truth; don't hand-edit formulas in either file (regenerate instead,
or your hand-edits will be lost on the next run).

```bash
python3 -m pip install openpyxl   # if not already installed
python3 build_workbook.py [output_path]      # defaults to ./COB_Calculator.xlsx
python3 build_workbook_ca.py [output_path]   # defaults to ./COB_Calculator_CA.xlsx
```

`build_workbook_ca.py` imports its styling constants and helpers directly from
`build_workbook.py` (same fonts, colors, number formats) -- run it from this
directory so that import resolves.

## Verifying it

**Run `recalc.py` on a COPY, never on `COB_Calculator.xlsx` or
`COB_Calculator_CA.xlsx` themselves.**
`recalc.py` uses LibreOffice, which rewrites the file it's given in place --
and LibreOffice's xlsx writer re-serializes some style/number-format codes
differently than openpyxl does (harmlessly for LibreOffice itself, but we hit
a real case where the result made Microsoft Excel refuse to open the file
without a "repair" prompt: LibreOffice turned a clean `yyyy-mm-dd` date format
into `yyyy/mm/dd`, and a clean `$#,##0.00;($#,##0.00);-` money format into a
garbled quoted/escaped equivalent). The shipped file must stay pure `openpyxl`
output -- that's what real Excel expects and opens cleanly. openpyxl doesn't
write cached formula values, but that's fine: `fullCalcOnLoad` is on by
default, so Excel computes every formula itself the moment the file opens.

```bash
cp COB_Calculator.xlsx /tmp/verify.xlsx
python3 <path-to-xlsx-skill>/scripts/recalc.py /tmp/verify.xlsx 240
```

Should report `"status": "success"`, `"total_errors": 0`. A clean recalc proves
the formulas *evaluate*, not that they're *right* -- see the design doc for how
values were additionally cross-checked against `cob_calculator` (COB-py), by
reading the verified COPY's cached values with
`load_workbook(path, data_only=True)` (never the pristine shipped file, which
has none until opened in Excel).

## Sheets

`COB_Calculator.xlsx` (US-style engine):

- **README** -- legend and assumptions, inside the workbook itself.
- **Segments, LumpSums, Overrides, PMI_Costs** -- inputs for the segmented
  mortgage engine.
- **Schedule, Summary, YearlySummary** -- computed (don't edit).
- **PaymentFrequency, ExtraPayment** -- standalone single-loan calculators.
- **Points, Refinance, CompareTerms, LTV_DSCR, ARM_Reset, Fees_APR,
  DTI_Affordability** -- standalone calculators, each with its own inputs.

`COB_Calculator_CA.xlsx` (Canadian Cost-of-Borrowing disclosure engine, see
[`docs/new-req/006-cost-of-borrowing-disclosure.md`](../docs/new-req/006-cost-of-borrowing-disclosure.md)):

- **COB_CA** -- inputs (Flow/Product type/Rate type dropdowns, common and
  flow-conditional fields, a per-fee Financed?/Included-in-COB? table) and
  all summary outputs (payment amount, trigger rate, COB amount/rate).
- **COB_CA_Schedule** -- computed amortization schedule for the current
  contract term only (don't edit).

## Optional VBA macros (COB_CA only)

`COB_Calculator_CA.xlsx` stays pure formulas -- no macros, matching the rest
of this project's "formula-driven, no macros" design. For users who
explicitly want real VBA (a chart of the amortization schedule, and a
one-click disclosure-summary PDF export), a companion module,
`COB_Calculator_CA_macros.bas`, ships alongside it. It is **not** embedded in
the `.xlsx` -- installing it means saving your own macro-enabled copy
(`.xlsm`) and importing the module once. See
[`MANUAL.md`'s "COB_CA macros" section](MANUAL.md#cob_ca-macros-optional-vba)
for exact steps, what each macro does, the Enable Content prompt you'll see
and why, and -- important if you ever touch `build_workbook_ca.py` again --
the regeneration story now that a macro-enabled fork of the file can exist
(short version: `build_workbook_ca.py` can refresh formulas *in place* inside
an existing `.xlsm` without disturbing its VBA project, but it still cannot
author or update the VBA *itself*; re-importing the `.bas` by hand is a
separate, manual step). This is why the `.bas` file is a genuine, standalone
VBA source file, not a build-script output -- see that MANUAL.md section for
why (no path exists to author VBA from a script on this platform; confirmed,
not assumed).
